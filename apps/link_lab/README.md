# `link_lab` — cFS Data Link Layer Application

`link_lab` is a cFS application written in Rust that implements a CCSDS data link layer (TM downlink transfer frames, TC uplink transfer frames with MAP demultiplexing and segment reassembly, and COP-1 FARM-1) using [Aldis](https://github.com/kscharpf/aldis), running unmodified on cFS v7.0.1 (`pc-linux` PSP).

## 1. Overview & Crate Boundaries

| Crate / Path | Role | Constraints |
|---|---|---|
| [`apps/link_lab/core`](core) (`link-lab-core`) | Sans-I/O link state machine (`Link`, `Level`, `DownlinkState`, `UplinkState`, `UplinkMode`, `LinkConfig`) | `#![no_std]`, `#![forbid(unsafe_code)]`, heap-free, panic-free, workspace flight lint set; depends on `aldis` and `refapp-scenario` only; no `cfe` or `cfe-sys` dependency |
| [`apps/link_lab`](.) (`link-lab`) | Thin cFS `staticlib` glue (`LINK_LAB_AppMain`, SB pipe dispatch, `step-lab-core::msg` wire encode/decode) | `#![no_std]`, `#![deny(unsafe_code)]` with one `#[expect]` on `LINK_LAB_AppMain`; linked with `--undefined=LINK_LAB_AppMain`, `--gc-sections`, and `link_lab.sym` (exports only `LINK_LAB_AppMain`) |
| [`crates/cfe`](../../crates/cfe) | Safe Rust wrappers over cFE (`es`, `evs`, `sb`, `msg`, `status`) and OSAL (`osal::TcpStream`, `osal::task_delay`) | `#![no_std]`; all app-side `unsafe` lives here with `// SAFETY:` comments; free of `aldis` |
| [`crates/cfe-sys`](../../crates/cfe-sys) | Raw `extern "C"` declarations and `#[repr(C)]` types generated by `bindgen` from `node_defs` mission headers | `#![no_std]`; declarations only; committed `src/bindings.rs` verified current on every `make node` run |

In the node test configuration, `link_lab` runs alongside two companion apps:

- **`step_lab`** ([`apps/step_lab`](../step_lab)): Bridge to `refapp-harness` over loopback TCP (`osal::TcpStream`) and lockstep sequencer (`START`, `WAKE_RX`, `WAKE_APPS`, `WAKE_TX`, `DONE`). Free of `aldis`.
- **`scn_lab`** ([`apps/scn_lab`](../scn_lab)): Scenario flight applications wrapping `refapp-flight::FlightNode`.

## 3. Integration Requirements

### Mission & target configuration (`node_defs/targets.cmake`)

Add the applications and startup script to the target CPU configuration in [`node_defs/targets.cmake`](../../node_defs/targets.cmake):

```cmake
SET(cpu1_APPLIST link_lab step_lab scn_lab)
SET(cpu1_FILELIST cfe_es_startup.scr)
include("${CMAKE_CURRENT_LIST_DIR}/check_msgids.cmake")
```

### Message IDs (`node_defs/node_msgids.h`)

Internal bus message IDs are defined in [`node_defs/node_msgids.h`](../../node_defs/node_msgids.h) outside cFE's reserved platform and global ranges (`0x0800..=0x087F` telemetry, `0x1800..=0x187F` command):

- Commands / turns: base `0x1900` (`NODE_CMD_MID_BASE`)
- Telemetry / data: base `0x0900` (`NODE_TLM_MID_BASE`)
- Harness TCP port: `NODE_HARNESS_PORT` (`5010`)

`_Static_assert` checks (`NODE_CHECK_MID`) verify at compile time that no node MID collides with cFE reserved ranges.

### Startup script & stack sizing (`node_defs/cpu1_cfe_es_startup.scr`)

Each app is started in [`node_defs/cpu1_cfe_es_startup.scr`](../../node_defs/cpu1_cfe_es_startup.scr) with a **64 KiB (`65536` bytes)** task stack because `Link` and its packet/frame buffers are held on the task stack with zero heap allocation:

```text
CFE_APP, link_lab, LINK_LAB_AppMain, LINK_LAB, 60, 65536, 0x0, 0;
CFE_APP, step_lab, STEP_LAB_AppMain, STEP_LAB, 70, 65536, 0x0, 0;
CFE_APP, scn_lab,  SCN_LAB_AppMain,  SCN_LAB,  65, 65536, 0x0, 0;
```

Measured stack usage (WP-6):

| App | Measured stack frame | Notes | Headroom (vs. 64 KiB) |
|---|---|---|---|
| `link_lab` | 40,144 bytes (~39.2 KiB) | `Link` is 7,480 bytes; `pending_tlm` buffer is 16,448 bytes | ~24 KiB |
| `step_lab` | 8,240 bytes (~8.1 KiB) | Sequencer collector and TCP framing buffers | ~57 KiB |
| `scn_lab` | 16,480 bytes (~16.1 KiB) | `FlightNode` state | ~49 KiB |

### Pipe depth & POSIX `fs.mqueue.msg_max`

`link_lab`, `step_lab`, and `scn_lab` create Software Bus pipes of depth **32** (`LINK_LAB_PIPE`, `STEP_LAB_PIPE`, `SCN_LAB_PIPE`) and use `Pipe::subscribe_ex` with per-MID limits up to **32** (cFE's default `CFE_PLATFORM_SB_DEFAULT_MSG_LIMIT` of 4 is smaller than a step's burst of telemetry packets).

On Linux (`pc-linux` PSP), OSAL silently truncates POSIX message queues to `/proc/sys/fs/mqueue/msg_max` (often 10 by default) without returning an error. Ensure `fs.mqueue.msg_max >= 32` (the [`Makefile`](../../Makefile) passes `--sysctl fs.mqueue.msg_max=64` to the container). At start-up, `step_lab` runs `cfe::sb::check_pipe_depth(32, NODE_TEST_MID)` and exits with a Critical EVS event if queue truncation is detected.

## 4. Internal Software Bus Interface

Scenario Space Packets travel wrapped inside internal Software Bus messages ([`apps/step_lab/core/src/msg.rs`](../step_lab/core/src/msg.rs), design §4.4) rather than as native cFE messages. Wrapping avoids MID collisions with cFE platform telemetry (e.g., APID `0x010` would map to `0x0810` in MID v1) and keeps scenario secondary headers untouched by cFE header routines.

| Message | MID | From → To | Payload | Purpose |
|---|---|---|---|---|
| `START` | `0x1900` (`NODE_START_MID`) | `step_lab` → `link_lab`, `scn_lab` | `LinkLevel` (`Packets`, `Frames`, `Cop1`) | Initializes link state for the case after `HELLO` |
| `WAKE_RX` | `0x1901` (`NODE_WAKE_RX_MID`) | `step_lab` → `link_lab` | `now`, one link unit (≤ 1024 B) | Process one delivered uplink unit |
| `WAKE_TX` | `0x1902` (`NODE_WAKE_TX_MID`) | `step_lab` → `link_lab` | `now`, `tx_slot` | Drain buffered `TLM_PACKET`s and pipe, then emit slot unit |
| `WAKE_APPS` | `0x1903` (`NODE_WAKE_APPS_MID`) | `step_lab` → `scn_lab` | `now` | Run scenario steps 2–5 (time-tags, dump, HK, payload) |
| `CMD_PACKET` | `0x1904` (`NODE_CMD_PACKET_MID`) | `link_lab` → `scn_lab` | `now`, one command packet | Deliver one extracted command packet (step 1) |
| `CMD_PACKET_DONE` | `0x1905` (`NODE_CMD_PACKET_DONE_MID`) | `scn_lab` → `link_lab` | — | Return turn after handling one command packet |
| `TEST` | `0x190F` (`NODE_TEST_MID`) | `step_lab` → `step_lab` | — | Startup pipe-depth truncation self-check |
| `TLM_PACKET` | `0x0900` (`NODE_TLM_PACKET_MID`) | `scn_lab` → `link_lab` | One telemetry packet (≤ 1024 B) | Submit telemetry packet for downlink |
| `RECORD` | `0x0901` (`NODE_RECORD_MID`) | `scn_lab` / `link_lab` → `step_lab` | `RecordKind` (`PacketOut`, `PacketIn`, `Event`), APID/code, data/args | Trace output record in production order |
| `UNIT` | `0x0902` (`NODE_UNIT_MID`) | `link_lab` → `step_lab` | One link unit (≤ 1024 B) | Downlink unit output |
| `DONE` | `0x0903` (`NODE_DONE_MID`) | `link_lab`, `scn_lab` → `step_lab` | `next_deadline` (`Option<u64>`) | Ends the app's turn and reports earliest deadline |
